# Beacon Global site — developer handoff

**Status:** proof of concept, built from the approved Claude Design prototype (`Beacon Global Website.dc.html`) and the build spec (`docs/build-spec.md`, updated Sept 24, 2026). It builds cleanly and passes `npm run check`. It is **not live** yet.

## Stack

| | |
|---|---|
| Framework | Next.js 16 (App Router), `output: 'export'`, `trailingSlash: true` |
| Styling | Tailwind v3.4, shadcn-style HSL variables in `app/globals.css`, mapped in `tailwind.config.ts` |
| Font | Inter via `next/font/google`. Self-hosted at build time, so visitors make no request to Google. The build machine needs network access. |
| Runtime JS | Next's own bundle, the mobile menu, the video pause control and the copy-mission button. No third-party scripts. |

## Moving into the God's Beacon repo later

The site is self-contained, so the plan is to copy this folder as-is (e.g. `apps/beaconglobal/` or `beaconglobal/`) and deploy it as a **separate Vercel project** with *Root Directory* set to that folder.

Check these against the primary repo first. They can't be verified from here:
1. **Next / React / Tailwind versions.** This uses Next 16.3 and React 19. If the product pins something older, either keep this folder's own `package.json` (simplest; works as long as the repo isn't a single-package workspace) or align versions.
2. **Package manager / workspaces.** This uses npm with its own `package-lock.json`. If the product uses pnpm or yarn workspaces, regenerate the lockfile with that tool.
3. **Token names.** `--background`, `--card`, `--primary` and the rest follow the product values in the spec. Confirm they match the product's `globals.css`, including whether values carry the `hsl()` wrapper. Extra tokens added here: `--primary-hover`, `--link`, `--link-hover`, `--eyebrow`, `--blue-900`.
4. **Lint/format config.** This repo has only `tsc --noEmit`. Run the product's ESLint and Prettier after moving it.

## Deploy (Vercel)

1. New Vercel project → import repo → Framework: Next.js (auto-detects static export) → Root Directory: this folder.
2. Domains: add `beaconglobal.org` and `www.beaconglobal.org`.
3. At GoDaddy, change **only the A/CNAME records** Vercel shows. **Do not move nameservers**, or Google Workspace email breaks.
4. Keep the Vercel preview URL for review; promote to production after QA.

## Deviations from the prototype (all intentional)

| Prototype | Build | Why |
|---|---|---|
| Hash routes `#/about` | Real pages `/about/` etc. | Spec sitemap; reviewers can land on any page directly |
| Google Fonts `<link>` | `next/font` self-hosted | Spec: no third-party connections except Stripe |
| `support.js`, `image-slot.js` | Removed | Claude Design editor runtime, not site code |
| Width detection in JS for the nav | CSS breakpoint at 880px | Works before JS loads; no layout flash |
| — | Skip link, `aria-current`, "(opens in a new tab)" text, reduced-motion stops video autoplay | Accessibility |
| Verses without translation labels (v2) | Labels added; Matthew 18:12 and 5:14 in exact NLT text | Owner decision; spec scripture rule |
| Photo credits only on Legal (v2) | Same, rendered at the bottom of `/legal/` | — |

## Verified by `npm run check`

On all 4 pages at 1280×800 and 390×844:
- the page loads and makes no third-party requests
- exactly one h1, alt text on every image, no horizontal scroll
- text contrast AA on solid backgrounds
- every link and button at least 44px tall (inline links in sentences are exempt under WCAG)
- a title, description and og:image on every page
- no placeholder copy, no EIN, a translation cited on every verse
- Give links point to the exact Stripe URL
- every internal link resolves

Home, desktop only: the legal name, 501(c)(3) and contact are above the fold at 1280×800, and the page says "Beacon Global, Inc. operates God's Beacon". Every page: the legal name is never written without the comma. Site-wide: sitemap.xml, robots.txt, the favicon and the OG image exist.

**Not covered by the script (manual QA still needed):**
- Text over photos (the scripture band and cards). Checked visually; scrims keep it readable, but confirm on real devices.
- The God's Beacon phone video (H.264). The test browser can't decode H.264, so playback wasn't tested here. Check in Safari (iOS) and Chrome.
- Lighthouse, screen reader pass, real-device Safari.
- Outbound links: godsbeacon.org, the terms page and Stripe.
